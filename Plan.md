# План рефакторинга проекта

## Цели

1. Превратить проект в устанавливаемый Python-пакет.
2. Обеспечить установку через:

```bash
pip install local-docs
```

3. Добавить консольную команду:

```bash
local-docs
```

4. Использовать только host-based архитектуру текущего `new_server.py`.
5. Ограничить сервер адресом `127.0.0.1`.
6. Открывать браузер по умолчанию.
7. Сохранить возможность отключения браузера через `OPEN_BROWSER=0`.
8. Разделить конфигурацию, HTTP-сервер, работу с файлами, hosts-файлом и браузером.
9. Добавить тесты и базовые проверки качества.

Каталог `sites/` остается локальным пользовательским хранилищем и не включается в Git-пакет по умолчанию. Путь к нему должен задаваться конфигурацией.

## Этап 1. Зафиксировать контракт приложения

1. Единственная поддерживаемая точка запуска:

```bash
local-docs
```

2. Дополнительный запуск через Python-модуль:

```bash
python -m local_docs
```

3. Сервер слушает:

```text
127.0.0.1
```

4. Порт по умолчанию: `8080`.
5. Если порт занят, сервер выбирает свободный порт.
6. Сайты доступны по адресам:

```text
http://site-name:<port>/
http://site-name:<port>/path
```

7. Страница списка сайтов доступна по адресу:

```text
http://127.0.0.1:<port>/docs_local
```

8. Браузер открывается по умолчанию.
9. Браузер отключается через:

```bash
OPEN_BROWSER=0 local-docs
```

10. Неизвестный Host должен получать `404`.
11. Все сетевые подключения должны быть доступны только локально через `127.0.0.1`.

## Этап 2. Перевести проект на пакетирование

Статус: [x] выполнено

Обновить `pyproject.toml`:

- имя distribution-пакета: `local-docs`;
- Python-пакет: `local_docs`;
- исходники разместить в `src/`;
- добавить console script:

```toml
[project.scripts]
local-docs = "local_docs.cli:main"
```

- перенести `pytest` и инструменты проверки в dev-зависимости;
- оставить `aiohttp` основной runtime-зависимостью;
- удалить `aiohttp-index` после удаления legacy-сервера;
- настроить включение HTML-шаблона в wheel/sdist.

Проверить локальную установку:

```bash
python -m pip install .
local-docs
```

Проверить сборку:

```bash
python -m build
python -m pip install dist/*.whl
local-docs
```

Важно: название проекта в PyPI и имя команды будут `local-docs`, а импортируемый Python-модуль должен называться `local_docs`.

## Этап 3. Реализовать CLI

Создать `local_docs/cli.py`.

CLI должен:

1. загрузить конфигурацию;
2. настроить logging;
3. обнаружить сайты;
4. запустить сервер;
5. обновить hosts-файл;
6. открыть браузер, если `OPEN_BROWSER=1`;
7. корректно обработать `KeyboardInterrupt`;
8. выполнить очистку hosts-файла при завершении.

Предусмотреть CLI-опции, переопределяющие переменные окружения:

```text
--host
--port
--sites-dir
--open-browser
--no-browser
--log-level
```

Значение по умолчанию для bind address должно быть `127.0.0.1`.

## Этап 4. Ввести конфигурацию

Создать `AppConfig`, который централизованно хранит:

```text
base_dir
sites_dir
bind_host = "127.0.0.1"
preferred_port = 8080
open_browser = True
log_level
template_path
hosts_path
```

Источники настроек по приоритету:

1. CLI-аргументы;
2. переменные окружения;
3. значения по умолчанию.

Поддержать:

```bash
HOST=127.0.0.1
PORT=8080
SITES_DIR=/path/to/sites
OPEN_BROWSER=1
LOG_LEVEL=INFO
```

Значение `OPEN_BROWSER` должно интерпретироваться как boolean. Значение по умолчанию: включено.

## Этап 5. Выделить реестр сайтов

Создать `SiteRegistry`, отвечающий за:

- поиск каталогов сайтов;
- исключение скрытых директорий и директорий, начинающихся с `_`;
- сортировку имен;
- сопоставление Host с каталогом;
- проверку существования сайта;
- проверку расположения каталога внутри `sites/`.

Нельзя формировать путь к сайту напрямую из произвольного Host-заголовка.

## Этап 6. Разделить HTTP-маршрутизацию

Создать приложение через функцию:

```python
create_app(config, site_registry)
```

Маршруты:

```text
GET /docs_local
GET /{tail:.*}
```

Разделить ответственность:

- `server.py` — создание и lifecycle `aiohttp`;
- `routes.py` — HTTP handlers;
- `site_registry.py` — поиск сайтов;
- `static_files.py` — безопасное разрешение файлов;
- `index_renderer.py` — генерация HTML списка;
- `browser.py` — открытие браузера;
- `hosts_manager.py` — управление hosts-файлом.

## Этап 7. Обеспечить безопасную раздачу файлов

Сохранить и усилить проверку через `Path.resolve()`.

Проверить:

- traversal через `../`;
- URL-encoded traversal;
- абсолютные пути;
- двойные слэши;
- неизвестные сайты;
- Host с портом;
- symlink на файл вне выбранного сайта.

Разрешить только пути, находящиеся внутри реального каталога соответствующего сайта.

Поддержать:

- `index.html` для директорий;
- обычные статические файлы;
- fallback `page.html` для запроса `/page`;
- ответы `403` и `404`.

Bind address не должен быть `0.0.0.0`.

## Этап 8. Переделать генерацию `/docs_local`

Убрать глобальную переменную `RUNNING_DOCS`.

Создать renderer, который:

- загружает шаблон из package data;
- принимает список сайтов и фактический порт;
- экранирует HTML-значения;
- безопасно формирует ссылки;
- сортирует сайты;
- возвращает готовый HTML.

Передавать renderer через состояние `aiohttp.Application` либо хранить его в объекте приложения.

Шаблон перенести в:

```text
src/local_docs/templates/index.html
```

Настроить включение шаблона в собранный пакет.

## Этап 9. Исправить lifecycle и выбор порта

1. Не использовать глобальный `SERVER_PORT`.
2. Не запускать startup callback вручную и через `on_startup` одновременно.
3. Использовать один механизм startup/shutdown.
4. Сохранять ссылку на задачу открытия браузера.
5. Отменять задачу при завершении.
6. Вызывать очистку hosts в гарантированном shutdown-блоке.
7. Использовать socket, открытый `aiohttp`, вместо отдельной проверки свободного порта.
8. После запуска получить фактический порт.
9. Только после получения фактического порта сформировать ссылки и открыть браузер.

## Этап 10. Сделать браузер частью конфигурации

По умолчанию:

```text
OPEN_BROWSER=1
```

Поведение:

- после запуска сервера открыть `/docs_local`;
- если `xdg-open` или GUI недоступны, сервер не должен завершаться;
- ошибки открытия браузера логировать;
- фоновой задаче задать timeout;
- при остановке сервера корректно отменять задачу.

Не смешивать браузерную интеграцию с HTTP-маршрутизацией.

## Этап 11. Изолировать управление hosts-файлом

Создать `HostsManager` с интерфейсом:

```python
update(domains)
clean()
```

Изменения:

- убрать `sys.exit()` из библиотечного кода;
- использовать исключения;
- обрабатывать ошибки в CLI;
- использовать logging вместо `print`;
- сохранить существующие маркеры;
- выполнять атомарную запись через временный файл и `os.replace`;
- корректно обрабатывать старый незакрытый блок;
- предусмотреть тестовый путь hosts-файла;
- не обращаться к реальному `/etc/hosts` в тестах.

Сохранить маркеры:

```text
# === AIOHTTP LOCAL SERVERS START ===
# === AIOHTTP LOCAL SERVERS END ===
```

## Критичные требования

- Distribution name: `local-docs`.
- Console command: `local-docs`.
- Python package: `local_docs`.
- Bind address: `127.0.0.1`.
- Browser opening: включено по умолчанию.
- Default setting: `OPEN_BROWSER=1`.
- Возможность отключения: `OPEN_BROWSER=0`.
- Сервер не должен быть доступен извне без явного изменения конфигурации.
- Управление системным hosts-файлом должно быть тестируемым и корректно очищаться при завершении.
